# Fully permissive policy

`permissive.te` marks every platform and vendor type permissive
(`permissive <type>;`), so the kernel logs every denial and enforces nothing.
It is generated by `generate.sh` from `sepolicy/aosp_provided_types.txt`
(2,952 types) and `sepolicy/vendor.te`.

## Kernel side is impossible

The stock kernel cannot be made permissive:

| Mechanism | Stock kernel | Why |
| --- | --- | --- |
| `enforcing=0` / `selinux=0` boot param | ignored | `CONFIG_SECURITY_SELINUX_BOOTPARAM is not set` |
| `/sys/fs/selinux/enforce` | read-only | `selinuxfs.c` compiles `sel_write_enforce` out without `CONFIG_SECURITY_SELINUX_DEVELOP` |
| `androidboot.selinux=permissive` | no effect | init writes to that read-only node |
| boot default | enforcing | `CONFIG_SECURITY_SELINUX_DEVELOP is not set` |

A kernel-side permissive build needs a kernel with `DEVELOP=y`, i.e. the
kernel source (not delivered).

## Debug only

This helper is a diagnostic, not a shipping path. With `X663_SEPOLICY_PORT`
off it would install a generic vendor policy plus 2,952 permissive domains in
place of the stock vendor policy, which is the opposite of the default stock
setup. Enabling it therefore stops the build unless the converted port is
enabled too.

## Enabling

`BoardConfig.mk`:

```make
X663_SELINUX_PERMISSIVE ?= false
```

Set `true` only for a local `userdebug` or `eng` debug session. `BoardConfig.mk`
raises a build error when it is `true` without `X663_SEPOLICY_PORT := true`, or
in any variant other than `userdebug` and `eng`.

## How to use

```
X663_SEPOLICY_PORT := true
X663_SELINUX_PERMISSIVE := true
```

Every denial shows up as `avc: denied ... permissive=1` — the working list
for completing the vendor SELinux port.
